# 用已测占用比较内存容量

在“配置分析”的内存卡展开“查看各容量与已测峰值的差额”。表格比较的是候选机器**实际可用物理容量（GiB）**和当前任务的已测物理占用峰值，旁边保留可用容量范围、提交量峰值以及首末记录日期。它帮助筛选值得验证的容量，不自动创建候选条件或勾选确认。

例如，独立合成任务的已测物理峰值为 17.5 GiB：

| 候选可用容量 | 相对已测物理峰值 | 选购时的含义 |
| --- | --- | --- |
| 16 GiB | 少 1.5 GiB | 当时的物理占用不能原样容纳，需要核对工作集回收或换页后的体验 |
| 24 GiB | 多 6.5 GiB | 可以作为验证候选；差额不是已经测出的空闲余量或性能收益 |

较低容量并不直接等于无法运行，因为应用缓存和工作集可能变化；较高容量也不直接等于体验达标。提交量含分页支撑，不能直接当作必须安装的物理容量。商品标称 GB、实际字节数和 Windows 的 GiB 读数需统一后比较。

近期初步内存观测与所选窗口的容量对照分开。所选 30/90 天里较早出现的物理高峰仍参与容量表，不能被最近七天的轻载抹掉；切换为七天范围时也不把更早任务偷偷带入。取舍摘要用差额筛选候选，已经测到较高容量需求时以当前容量作基线。已确认的新需求、近期体验问题和正式压力判断保持优先。

数据仍按同一硬件配置与所选场景隔离。取得至少五分钟、覆盖至少 95% 的物理内存读数后才显示表格；历史异常或未隔离硬件时不生成容量对照。这里不放宽正式余量与代表性确认条件，当前分析方法仍为 1.15。

界面与 HTML 使用同一组数值。普通刷新保留展开状态；正式候选比较继续使用用户核对的目标、报价来源与任务结果，表格不将任何容量标为已通过。
