# 下一台电脑配置草案

开发中的 0.8.30 在“配置分析”顶部及 HTML 报告中，自动整理处理器、内存、显卡和 SSD 的优先比较方案。仅生成只读建议，不添加候选、核对条件或覆盖确认。已有比较文件仍为 comparison-1.4；分析方法仍为 1.15。

## 如何选择比较方向

- CPU 使用最近 7 天、当前场景的整机与最忙逻辑核心时长加权 P95，以及整机 ≥90% 的累计秒数。至少取得 5 分钟有效读数且两项覆盖均 ≥95% 后才生成新的草案方向。单核峰值不会独自生成更多核心的购机要求。整机 P95 <50% 且未记录 ≥90% 秒数时，先比较单核响应相近的主流、较少核心候选；P95 ≥80% 或已有 ≥90% 秒数时保留多核任务基准；其余比较单核与多核吞吐。50%/80% 是公开的比较顺序启发式，未经跨机器收益校准，不是瓶颈诊断或型号性能预测。需求、体验、历史异常及现有压力状态优先，不能凭这组数值绕过。
- 内存使用所选窗口的物理峰值和已测可用容量，提交量独立展示。已有轻载观测且没有优先事项时，从 8、12、16、24、32、48、64 等 **GiB 可用容量**对照值中，选择不低于物理峰值的一档；非轻载保留当前已测可用容量作基线。已有内存压力状态且物理峰值达到已测可用容量的 90% 时，优先比较更大一档；仅高提交量不触发这个容量建议。更大一档不自动判定必要，也不保证改善卡顿。它们是可用容量对照值，不是对商品标称的换名。
- 已核对的内存数量目标另外按商品 GB 规格提出检索档位，保留严格/非严格上下界。例如“内存大于 64 GB”先比较 96 GB 档；只有上限、没有可用基线时，不猜一个低容量。**商品 GB 条件与实测 GiB 可用容量不互相替代**。显卡共享内存也不能当作独立显存。
- SSD 将最新固定卷合计占用由 GiB 换成十进制 GB，再从 256/512 GB、1/2/4 TB 等档位中选择优先比较值。已有 ≥90% 空间压力时比较更大容量。明确的用户上限低于当前占用时保留该上限，并指出需要释放或外迁文件，不将观测偏好伪装为输入冲突。增长量不自动预测，容量不推断 SSD 速度。
- GPU 复用已有分引擎和核心/3D 购机顺序：轻载先比较核显与较低档独显；媒体任务核对媒体功能；重任务及近期需求保留。当前情景有正的独立显存下限时，先比较独显，不拿核显共享内存抵数。

GiB 与 GB 的换算依据为 [NIST 二进制前缀说明](https://physics.nist.gov/cuu/Units/binary.html)：1 GiB = 1,073,741,824 字节，1 GB = 1,000,000,000 字节。商品实际使用方式与系统预留仍需查资料及机器读数。

## 条件与缺口

必需条件形成基础草案；同一触发条件与必需条件合并形成各自方案，不同条件不猜测同时成立。用途待核对的事实继续保留各自分支，复用候选比较已有的事实身份规则，附触发条件与原文。内存、显存或存储自身的数量上下界冲突只撤下对应容量档位，其他配置项仍显示。

历史异常、缺失硬件身份或不足的读数不能生成观测容量档位；明确的独立需求仍能提供数量目标。切换范围或保存新需求时立即撤下旧草案，等待当前分析完成；普通刷新保留主面板的展开状态。

草案还没有将 CPU/GPU 映射成可靠的具体新型号，也没有自动提供当前可买商品与报价。它用于缩小比较范围，不能代替候选机的功能、体验和同任务测量，不能宣称商业成熟。
