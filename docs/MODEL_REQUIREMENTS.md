# 可替换模型解析与逐项核对

0.4.0 将模型接口接到原生界面和购机条件。未内置或默认启动模型，不保证任意模型都能正确理解需求。上一轮小模型的失败记录仍保留，不因接口可用就变成质量通过。

## 用户流程

1. 在记录设置填写需求原文，打开“模型解析与逐项核对”。
2. 填写支持 JSON Schema 聊天接口的完整地址、模型名和可选 API 密钥。接口采用兼容的 `chat/completions` 消息格式；仅支持该协议及结构化输出的服务。不自动选择或调用任何收费服务。
3. 点击发送时，只发送需求描述和通用提取指令，不附加硬件、进程、采样或历史记录。远程接口要求 HTTPS，回环地址允许 HTTP；不跟随重定向。
4. 候选事项默认不选用。逐项核对名称、类型、肯否/条件/不确定、过去/现在/未来、内容、单位、触发条件和逐字依据；可以补充遗漏或排除错误事项。
5. 勾选确认完整原文后保存。更改事项会清除旧确认；更改原文会取消待完成请求、废弃旧候选，保存更改后移除旧的已确认条件。

密钥仅在当前窗口的内存中保留，不写入设置或报告，退出时清空。当前还没有系统凭据库持久化。接口地址和模型名随确认的事项保存；地址中不能携带用户凭据、查询参数或片段。首次配置与重复使用的体验仍需继续完善。

## 条件如何参与配置建议

- 陌生软件名称保持开放，不强行塞进既有五个场景；未来明确任务会约束历史余量与降档候选，要求候选机器重跑验证。
- 明确的资源要求按可辨认的部件关联；例如内存下限不自动增加显卡要求。当前仍未将所有数值、单位与比较运算归一化成完整配置求解器。
- 条件、不确定和过去需求分别保留。条件与不确定事项不作为必然需求；报告提示分别比较触发与不触发条件的配置。带实际触发条件的事项不能保存为无条件要求。
- 预算、便携、噪声、功耗和兼容性展示在购机条件中，要求逐项检查候选机器；不会被翻译成更高 CPU/GPU 档位。当前没有自动价格库或完整候选过滤闭环。
- 用户确认及原文匹配都不能证明模型语义正确，不能代替真实性、完整性和候选机器实测。

## 运行边界

本机服务会改变被测占用。调用回环地址时，程序暂停自己的监测，并在结束后保持暂停，提醒先停止服务再继续。程序不管理用户已有模型服务的完整生命周期，也不能消除服务在调用前或恢复后对系统的影响；默认不常驻本机模型。此处是当前限制，尚不能声称本地推理开销已经完全隔离。

远程模型有 90 秒整体超时、取消、响应大小及字段上限。错误界面不展示提供方响应正文或请求头。修改原文、取消或接口错误不会覆盖已保存的需求；只有显式保存才改变确认状态。

## 验证与复现

原生界面测试通过受控 HTTP 响应验证输入、编辑、确认、保存、报告及取消链路，不是模型准确性测试。`tests/PerfCompass.ModelProbe` 则调用真实提供方，输出未确认候选；只验证接入和结果呈现，不自动生成购买结论。

```powershell
.tools/dotnet/dotnet.exe run --project tests/PerfCompass.ModelProbe -- <聊天接口地址> <模型名> <UTF-8需求文件> <输出JSON路径>
```

可选密钥由该测试进程的 `PERFCOMPASS_MODEL_KEY` 环境变量提供；程序不输出它。不要将密钥写在命令参数、输入文件或接口 URL 中。

真实本地提供方检查使用独立 llama.cpp / Qwen3-4B 服务、CPU 四线程和合成星图任务描述。发现并修复内层消息的中文 Unicode 字面转义问题后，服务返回了星图任务和预算两项候选，用时约 30 秒；这只说明该请求链路可用，不是泛化质量结论。之前 36 条规则诊断和 16 条模型实验仍见 `NLP_RESEARCH.md`。
