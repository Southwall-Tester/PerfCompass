# 原文事实与购机用途

原文的肯否、时间与这次选机的用途分别保存。过去发生过的卡顿可以仍需解决；“不允许丢帧”和“不要求更快”都是否定表达，却不能自动变成相同的购机条件。

## 核对流程

在记录设置打开“逐项核对需求”。可以手工补充事项，也可以按需使用已配置的模型提取候选。对照原文检查事项、关系、时间、内容、单位、触发条件和引用，最后选择购机用途：

| 购机用途 | 分析与候选比较 |
| --- | --- |
| 仍需满足或验证 | 保留任务或目标；满足明确数量语法及引用检查的条件可生成数值目标 |
| 必须避免 | 核对完整禁止事项；不自动反转数值方向，也不据此猜测需要哪一部件 |
| 不作为购机条件 | 原文仍保留在记录与报告中，本次不生成候选条件 |
| 用途待核对 | 保留核对分支，不能因原文是过去或否定表达就恢复降档方向 |

修改任一事项字段会撤销该项用途与整份原文的核对。用途放在原文字段之后选择；勾选纳入与保存时不会自动把待核对内容变成必需需求。条件与尚未确定的事项继续保留触发分支，不因为选择“仍需满足”就成为无条件需求。

已有繁忙、重任务和历史曲线作为独立观测继续保留。普通容量观测与明确的新容量目标同时保留，选机先核对新目标；已测峰值不自动替代用户确认的更大容量要求。过去的数值目标只有在明确选择仍需满足后才可能编译；来源数字、单位与方向检查仍执行。必须避免或用途待定的内容不自动生成相反的容量、金额或耗时边界。

## 条件来源改变

改变用途或原文会撤销比较覆盖确认。请重新导入当前范围；过期的来源条件会显示提示，不能直接据此把所有候选判成购机失败或计算节省。

原条件、引用、目标与测量不会自动删除。可以删除已经不需要的条件，或选择“保留所选为独立目标”，再修改并核对自己的目标。转为独立目标会撤销它的核对与比较覆盖确认，原始测量不改写。没有本机文字计划的电脑仍可独立核对带来的候选目标。

## 协议与旧记录

模型提取的八字段接口和 schema 保持 `semantic-1.0`。模型不能通过这个接口填写人工购机用途；候选也仍不会自动选用。确认计划使用 `semantic-plan-1.1`，将 `DecisionUse` 与原文、用户核对时间一起保存。

旧确认计划保留原文和事实，明确的当前/未来肯定条件沿用原有处理；过去或排除事项的用途先待核对。普通肯定条件保留旧来源标识，避免重新导入时重复创建相同目标。过去/排除事项的新解释不能继承旧的无条件核对。

新版计划缺少用途或含未知用途/协议时，程序提示重新核对，不能当作没有需求。异常内容摘要参与比较范围，内容改变后要重新确认。旧版客户端不理解新增用途，不支持使用旧版继续编辑新版确认计划；不声称旧程序能正确分析新计划。兼容的旧计划可在新版中核对并保存升级。

`SemanticFact.Label` 的旧展示字段为兼容来源标识而保留；新界面和报告分别展示原文关系、原文时间和购机用途。处理逻辑使用结构字段，不从展示名称猜测用途。

## 研究依据和验证边界

[Matsuyoshi 等，LREC 2010](https://aclanthology.org/L10-1469/) 分开表示事件的来源、时间、条件、实际性和评价等属性。[nl2spec](https://arxiv.org/abs/2303.04864) 及其[开源实现](https://github.com/realChrisHahn2/nl2spec)把形式化片段对应回原文，并允许交互修正。这里借鉴属性分离和原文对应的思路；将购机用途作为单独核对项是本项目的设计推论，两项研究都没有验证本软件或中文购机语义。

本轮检查针对已给定或人工核对的事实到配置判断、候选目标的连接，不是新模型准确率实验。不同任务名、肯否、时间、用途、条件、数量及编辑顺序使用同一套规则；测试中的人工事实和选项不能冒充模型已正确理解这些句子。

既有 8B 模型的开发审阅仍为 36 例中 7 完整、11 遗漏、18 错误，另 24 条扩展输入为 4 完整、1 遗漏、19 错误。原始输出、哈希与分类不改写，没有因为用途编译层的修复而提分。模型默认仍关闭，通用抽取质量、独立人工标注及真实用户验证仍未通过。
