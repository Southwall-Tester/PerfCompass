# 用一次实际任务缩小购机范围

这条流程适用于准备下一台电脑时的初筛。先写清要解决的问题，再比较具体候选；程序的观测方向、商品规格、报价与候选机任务结果各自保留依据。

## 先保留重要任务

在当前电脑记录一次常用工作组合和最重任务：选择实际场景，同时打开平时会并行使用的应用；出现卡顿或其他体验问题时记录发生时间与体验。较长时间的日常记录用于补充偶发任务与时期变化。

最近新增的任务单独写入需求并核对用途。过去发生的问题可以明确选为下一台仍要解决的目标；尚不确定是否会做的任务保留为条件。过去长期闲置不能抵消最近新增的重任务，观察到用户打开一个程序也不能直接认定需求已改变。

在“配置分析”查看当前取舍及其依据。初步轻载、容量差额和 GPU 比较顺序用于选出值得比较的方向；它们不自动证明较低配置达标。已有繁忙、体验问题、新需求或所选窗口中的重要重任务时，继续保留这些任务作为候选核对内容。没有记录的旧任务仍是未知。

## 先看配置建议与接近的型号

在“配置分析”的四部件草案下直接看参考机型：型号、参考配置、选择理由、来源和资料核对日期。无需导入商品，不需要商家接口或候选机测量。条件成立时的参考另列；库内没有接近的配置时会直说，不强塞型号。

当前参考库较小，仅含部分笔记本。路线/标称容量接近不代表 CPU/GPU 性能等同；新需求、实测可用内存和实际任务表现继续按上方依据选择。

## 可选：进一步精确比较

需要精确比较时，再到“候选配置”手动记录一至三套整机，也可用规格摘录辅助填写。此步骤不影响直接查看参考型号。

规格资料与报价分别填写。报价记录对应配置、金额、出处和查询日期；摘录时间只是本机记录时间。缺少报价不妨碍先核对任务和规格，但缺少报价来源的金额不参加预算优先或价差计算。商品内存 GB 与遥测可用 GiB 分开核对，共享显存不能当作独立显存。

导入当前需求与近期任务，逐项核对比较方向、数值、单位和触发条件。把“必须满足”与“只有接到某项目才需要”分开；不同条件不推定同时成立。边界冲突时先修正条件，不把所有商品都解释成不合格。

## 在候选机复测决定预算的任务

选一个能够改变选择的任务，例如编译自己的项目、按指定设置转码一份固定文件，或同时使用一组工作应用。先写可接受的耗时或体验目标，以及软件版本、输入、设置、电源模式和产物核对方法。

能自行退出的 EXE 可使用“任务测量”：保存同一方案，带到各候选机重新选择本机文件、核对环境，再主动运行重复测量。程序不会因为导入文件就执行任务。游戏帧率、交互延迟、噪声或软件兼容性需要采用适合该任务的方法取得结果，并在比较页明确保留人工核对或手填数值依据。

测量记录的是所选根进程启动至退出的耗时。退出码 0 仍需核对实际产物；后台分离任务不能仅凭根进程退出判断完成。失败、超时、取消、协议或电源不符的轮次，不能当作成功的短耗时。具体操作见 [任务测量与方案复用](TASK_MEASUREMENT.md)。

## 用结果作出取舍

逐项核对来源、机器与可比性，确认覆盖重要任务后点击“保存并比较”。先看必需条件，再分别看条件成立时的方案；尚未验证的条件继续显示待核对。一套候选也可以先完成独立核对。

在有来源且通过对应条件的候选中，查看预算优先方案。对更贵的候选，判断它是否改善了自己关心的任务、是否带来其他损失；额外容量或更高型号本身不代表值得加价。耗时区间重叠时，不只凭中位数宣称更快。程序不替用户给不同任务分配价值权重。

如果还缺关键任务证据，保留草稿并列出下一项要验证的内容。导出的 HTML 可用于保留本次比较依据；重新编辑需求、候选或测试条件后，要重新核对失效项目。候选状态的“必需条件通过”可能包含规格资料、人工核对和手填结果，只有对应原始重复耗时项目通过检查时，才显示“重复耗时测量达标”。

本会话刚完成的测量可在所选任务行点击“使用本次测量”，核对来源机器与目标后填入，省去寻找 JSON 文件。该操作不会自动认定当前电脑就是候选机，也不会自动确认任务达标；跨电脑测量仍通过原始文件导入。

当前支持与实测范围见 [试用版支持范围](SUPPORT_SCOPE.md)，具体比较规则见 [候选比较](CANDIDATE_COMPARISON.md)。
