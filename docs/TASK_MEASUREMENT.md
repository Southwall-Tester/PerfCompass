# 重复任务测量与结果导入

0.6.0 的“任务测量”用于能自行退出的编译、转码和批处理程序。记录所选根进程从启动到退出的墙钟耗时，包括进程启动开销；不测量游戏帧率、交互延迟，也不能用来确定已分离后台任务的完整完成时间。

0.8.16 增加可跨电脑复用的测量方案：在一台电脑填写一次任务、参数、版本、步骤和重复方式，保存后带到候选电脑重新定位本机文件，再显式运行。方案本身不含测量结果，复用方案也不代替候选电脑上的实际测试。

## 测量与比较

0.8.21 的测量记录使用 `task-measurement-1.1`，方案使用 `task-plan-1.1`。运行前取得所选 EXE 和输入文件的只读共享句柄，并保留至全部轮次及末次校验结束；普通写入、删除与文件替换会被 Windows 共享规则限制。其他程序已打开写入句柄时，在启动任务前提示处理占用。若任务需要就地处理数据，请选择不变的源输入，让任务从它创建工作副本再处理，输出另存，并在参数和步骤中写明这项安排。没有修改文件属性或目录权限。

旧版 1.0 文件可读取，原始轮次和协议保留。旧记录只在整批前后校验文件，不能证明各轮输入一致，因此不能再自动标为当前重复耗时达标。导入方案时先核对旧指纹，再复用任务字段到新方法，清空本机路径与环境确认，要求重新测量；不会改写导入源文件，也不继承旧耗时。新旧方法指纹不同，需要为新测量建立新的比较目标。其他已核对的独立规格或任务结果继续各自判断。

1. 在“任务测量”选择 EXE、工作目录、参数、软件版本、实际输入文件或输入清单，填写统一步骤、设置与产物如何核对，以及电源/性能模式。输入文件用于校验，不会自动拼进程序参数。
2. 选择 3/5/7 次正式测量，可先预热一次；预热不计入正式结果。单轮超时可设 1–600 秒。点击运行才会启动所选程序，打开或导入测量文件不会执行其中的参数。
3. 测量前暂停本实例的长期记录。程序在保持所选文件只读期间校验 EXE 和输入，再串行运行任务，记录每轮耗时、退出码、根进程退出状态和电源状态，最后复核所持文件内容。成功、失败、取消、超时或方案不匹配退出后释放本次文件句柄。校验读取输入，会影响缓存状态，不是冷缓存测试。
4. 结果自动保存在同一数据目录的 `measurements/`，可主动导出 JSON 带到另一台电脑的比较页。自动保存失败时保留内存中的结果和导出入口，先导出到可写目录。失败、超时或取消的记录供排查使用，不能作为成功的短耗时。
5. 在“候选配置”创建实际任务测量目标，指定至少/不超过及秒/s 或毫秒/ms，填写步骤并生成结果行。选中对应候选的任务行后导入文件。核对来源机器、测试过程与实际产物，重新确认目标和可比性后才参与判断。

同一目标第一次导入时绑定测量协议。其他候选需要相同程序校验值、参数、软件版本、输入校验值、步骤、重复/预热策略和电源环境声明；硬件型号可以不同。协议不同需新建目标保留不同协议的结果，不能混成一组比较。

## 把同一方案带到候选电脑

1. 在“任务测量”填写完整任务并选择实际文件，点击“保存测量方案”。无需先运行；保存只读取程序和输入文件计算校验值，不执行参数，也不生成测量结果。文件校验期间暂停长期记录，结束后保持暂停，可按需继续。
2. 将方案 JSON 以及实际需要的软件和任务文件分别带到候选电脑。方案不打包程序或输入，也不保存所选 EXE、工作目录和输入文件的本机路径字段；原样参数、步骤和其他手填文字仍可能包含路径，分享前需自行核对。跨电脑宜使用相同文件名和一致的相对路径参数。
3. 点击“导入方案或既有测量”。也可选择原始 1.0/1.1 测量文件，从中提取方案；旧机器身份、各轮耗时和旧结果不会成为本机测量。旧版按新文件保护方法复用时会明确提示。导入后清空三个本机路径，任务名称、参数、软件版本、步骤、电源声明、重复/预热和超时保持锁定。重新选择本机程序不会自动覆盖方案的软件版本声明。
4. 重新选择本机 EXE、工作目录和输入文件，并实际核对本机电源/性能模式、软件设置及输入安排，再勾选环境核对。导入时该勾选为空，重新保存导入方案也不会自动确认；之后改变本机路径需重新核对。本机自行填写后保存的方案沿用本次环境声明；环境核对是用户声明，不是程序已经检测或设置了所有性能模式。
5. 点击“运行并重复测量”。运行前重新校验程序及输入的文件名和内容、协议字段及插电/电池状态；与绑定方案不一致时不启动任务。运行后产生本机的新测量文件，带回比较页，选中对应候选的任务行再导入。程序不会自动把方案、机器或结果关联到某个候选。

需要改参数、版本或测试步骤时，点击“作为新方案编辑”解除锁定，再保存新方案或重新运行。该操作本身不改写原方案文件；另存时选择新文件名以保留原方案。改变后的协议不能沿用原目标的测量对照。无效文件或取消导入保留当前设置；保存方案也保留已有测量结果。

## 保存失败与退出

已经取得但尚未保存的测量结果会留在当前界面。编辑设置不会改写它；导入另一方案、新方案编辑和新运行会先要求导出，避免覆盖唯一结果。保存方案失败或取消不清除这份结果，测量导出失败也可以重试；成功保存或导出后才解除该保护。

退出会先取消并等待正在进行的测量操作。操作尚未结束时返回测量页；若仍有未保存结果，默认返回导出，只有明确选择放弃才退出。关闭到托盘继续保留当前会话。这是当前进程中的结果保护，不提供崩溃、断电或磁盘损坏后的恢复保证。

## 怎样判断够用

记录中位数及全部正式轮次的范围，配置判断使用全部已观测轮次：

- 对“耗时不超过 12 秒”，三次都不超过 12 秒才通过；三次都超过则不满足；9、10、14 秒这类跨过目标线的结果保留待验证。
- 不用中位数 10 秒掩盖一次 14 秒，也不将几次测量的范围当作统计置信区间或未来表现保证。
- 电源改变/未知、非零退出、未完成、协议不匹配，或手改显示值后与原始记录不一致，均不能作为有效的重复测量通过依据。
- 退出码 0 只能说明程序报告正常退出。任务是否完成正确、是否使用了对应候选机器和所声明设置，仍需核对。

## 记录与运行边界

记录包含程序文件名及校验值、原样参数、软件版本、输入文件名及校验值、步骤、机器 CPU/GPU/物理内存、OS 和电源信息。不保存所选 EXE、工作目录及输入文件的路径字段；参数、步骤等手填文字若包含绝对路径，仍原样保留在记录和导出中。标准输出与错误输出同时排空但不留存。文件不自动上传，不随采样保留期清理。

校验值用于辨认协议及选定文件变化，不是来源签名，也不证明所有引用文件、依赖库、环境变量或清单内容都已覆盖。请保证所选输入/清单能标识实际任务。输出重定向和监测本身可能影响运行方式或耗时，当前不是经过跨硬件校准的独立基准测试套件。

取消与超时会尝试终止本次启动的进程树，并记录根进程是否退出；不保证已分离、提权或脱离父进程的任务都被停止。测量后保持暂停，确认任务结束再继续长期记录。本程序不控制其他监测实例、外部模型服务或后台负载。

当前比较文件为 `comparison-1.3`，测量和方案升级为各自的 1.1；旧客户端会拒绝新测量/方案版本，含新测量的比较文件也不会被它继续读取保存。新版本可保留旧结果，但不会补造旧版缺失的保护证据。文件读取有限长、拒绝重复成员并检查所附协议指纹，不执行内容；指纹不代表身份认证。方案保存先写同目录临时文件，再发布完整文件；写入或替换失败时不覆盖已有目标。

只读共享保护适用于所选文件的普通文件打开方式；不将它描述为冻结整棵工作目录、全部依赖或所有映射与存储方式。选择清单只保护清单文件，不自动读取并保护里面列出的路径。原有可写映射、路径/目录替换、网络及特殊文件系统尚未完整验证。任务忽略写入失败而自行返回 0 时，程序仍只能记录该退出码，不能据此证明产物正确。

实现依据为 [.NET FileShare](https://learn.microsoft.com/en-us/dotnet/api/system.io.fileshare?view=net-10.0) 和 [Windows CreateFile 共享模式](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)。本机普通读写、替换与真实子进程检查见验证记录；文档语义不代替本机实测或其他存储环境验证。

## 验证范围

自动回归验证范围判定、协议隔离、旧文件升级、文件读写及真实开发进程的正常退出、大量输出、取消、超时和输入变化。原生界面流程使用受控 cmd/ping 任务验证生命周期和导入；合成候选与目标用于验证界面联动，不代表真实机器之间的性能比较，也不证明商业成熟度。
