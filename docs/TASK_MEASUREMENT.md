# 重复任务测量与结果导入

0.6.0 的“任务测量”用于能自行退出的编译、转码和批处理程序。记录所选根进程从启动到退出的墙钟耗时，包括进程启动开销；不测量游戏帧率、交互延迟，也不能用来确定已分离后台任务的完整完成时间。

## 测量与比较

1. 在“任务测量”选择 EXE、工作目录、参数、软件版本、实际输入文件或输入清单，填写统一步骤、设置与产物如何核对，以及电源/性能模式。输入文件用于校验，不会自动拼进程序参数。
2. 选择 3/5/7 次正式测量，可先预热一次；预热不计入正式结果。单轮超时可设 1–600 秒。点击运行才会启动所选程序，打开或导入测量文件不会执行其中的参数。
3. 测量前暂停本实例的长期记录。程序先校验 EXE 和选定输入文件，再串行运行任务，记录每轮耗时、退出码、根进程退出状态和电源状态，最后复核程序与输入未改变。校验读取输入，会影响缓存状态，不是冷缓存测试。
4. 结果保存在同一数据目录的 `measurements/`，可主动导出 JSON 带到另一台电脑的比较页。失败、超时或取消的记录供排查使用，不能作为成功的短耗时。
5. 在“候选配置”创建实际任务测量目标，指定至少/不超过及秒/s 或毫秒/ms，填写步骤并生成结果行。选中对应候选的任务行后导入文件。核对来源机器、测试过程与实际产物，重新确认目标和可比性后才参与判断。

同一目标第一次导入时绑定测量协议。其他候选需要相同程序校验值、参数、软件版本、输入校验值、步骤、重复/预热策略和电源环境声明；硬件型号可以不同。协议不同需新建目标保留不同协议的结果，不能混成一组比较。

## 怎样判断够用

记录中位数及全部正式轮次的范围，配置判断使用全部已观测轮次：

- 对“耗时不超过 12 秒”，三次都不超过 12 秒才通过；三次都超过则不满足；9、10、14 秒这类跨过目标线的结果保留待验证。
- 不用中位数 10 秒掩盖一次 14 秒，也不将几次测量的范围当作统计置信区间或未来表现保证。
- 电源改变/未知、非零退出、未完成、协议不匹配，或手改显示值后与原始记录不一致，均不能作为有效的重复测量通过依据。
- 退出码 0 只能说明程序报告正常退出。任务是否完成正确、是否使用了对应候选机器和所声明设置，仍需核对。

## 记录与运行边界

记录包含程序文件名及校验值、原样参数、软件版本、输入文件名及校验值、步骤、机器 CPU/GPU/物理内存、OS 和电源信息。不保存所选 EXE、工作目录及输入文件的绝对路径；参数若包含绝对路径，仍原样保留在记录和导出中。标准输出与错误输出同时排空但不留存。文件不自动上传，不随采样保留期清理。

校验值用于辨认协议及选定文件变化，不是来源签名，也不证明所有引用文件、依赖库、环境变量或清单内容都已覆盖。请保证所选输入/清单能标识实际任务。输出重定向和监测本身可能影响运行方式或耗时，当前不是经过跨硬件校准的独立基准测试套件。

取消与超时会尝试终止本次启动的进程树，并记录根进程是否退出；不保证已分离、提权或脱离父进程的任务都被停止。测量后保持暂停，确认任务结束再继续长期记录。本程序不控制其他监测实例、外部模型服务或后台负载。

比较文件升级为 `comparison-1.1`，旧版条件与核对状态保留。旧客户端会拒绝覆盖这个版本，避免丢弃它不理解的重复测量证据。测量文件版本为 `task-measurement-1.0`；文件读取有限长及结构验证，不执行内容。

## 验证范围

自动回归验证范围判定、协议隔离、旧文件升级、文件读写及真实开发进程的正常退出、大量输出、取消、超时和输入变化。原生界面流程使用受控 cmd/ping 任务验证生命周期和导入；合成候选与目标用于验证界面联动，不代表真实机器之间的性能比较，也不证明商业成熟度。
