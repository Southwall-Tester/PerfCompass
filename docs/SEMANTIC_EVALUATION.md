# 模型语义审阅协议

本协议区分传输、格式、引用定位、语义保留与产品中的约束转换。任何一层通过，都不能替代其余层。评估对象是合成输入与当前模型、量化、运行器、提示词、采样设置的组合，不是所有用户或模型的一般准确率。

## 输入与复现

原有 `tests/nlp-cases.json` 的 36 条输入保持不变，不删除旧失败例，不修改预期去迁就模型输出。实验通过产品 `ModelRequirementExtractor` 发送原始描述，使用产品提示词与 schema。记录模型、提示、schema、用例集和运行器的 SHA256，分别保留每例原始候选、耗时及协议失败。研究脚本只绑定回环地址、按需启动自建进程，并在批次结束后核对其退出；不安装常驻服务。

模型运行会占用当前电脑的 CPU 和内存。实验不写入用户历史或生成购买建议，但不能声称其他已经运行的监测实例完全看不到这些真实负载。

新实验脚本还记录自建服务从启动到推理结束的进程峰值工作集和 CPU 总时间，并保留参与运行的程序集哈希。峰值工作集不是系统提交量；CPU 总时间不是整机占用百分比。旧实验未采集的字段不补造。

现有用例曾参与开发和提示设计，因此属于开发诊断集，不是盲测或独立测试集。开发代理逐例审阅也不能代替独立人工复核、真实用户试用或跨硬件验证。

## 逐例检查

审阅时对照完整原文，检查以下内容：

- 对象与作用范围：任务名称开放；电脑重量不变成背包重量；组件预算不变成整机预算；显示器刷新率不变成任务帧率。
- 肯否与条件：不能把否定、尚未确定或条件未触发的事项变成无条件必需；条件和否则分支分别保留。
- 时间：原文明确的以前、现在、将来不互换；过去发生过任务不等于该任务已永久取消，近期体验与退役需求不能混为一谈。
- 数字与单位：上下限、范围、容忍度、规模、频率、增长和费用包含范围不丢失，不自行推算原文没有明确提出的配置要求。
- 完整性：小概率任务、并发、多用户、噪声、功耗、兼容性、便携与时间安排同样纳入核对，不能仅保留几个熟悉任务。
- 澄清：针对真正缺失的决策信息提问；不能重复追问原文已经回答的信息，也不能用问题代替抽取已给的事实。
- 推断与指令：不能从卡顿直接推断缺显卡，不能伪造测试、执行描述中的指令或直接购买最贵配置。

允许合理同义词与不同拆分粒度，前提是完整保留各项关系。引用能在原文定位，不代表该引用支持模型填写的主体、肯否、时间或数值。

## 审阅分类

每例使用一种主分类，并记录具体问题：

- `complete`：在本协议和该例原文范围内，未发现影响购机条件的信息遗漏或错误，澄清没有明显矛盾。仍是开发审阅结论。
- `incomplete`：有重要遗漏或无必要的澄清，但已输出的事项未发现明显相反或捏造的要求。单独列出重要数值遗漏，不认为它们无害。
- `incorrect`：存在明确的对象、肯否、条件、时间、数值或作用范围错误，或添加原文不支持的要求。
- `failed`：模型调用、生成完整性或格式失败，未得到可审阅候选。

未经审阅的记录保持 `unreviewed`。完整率只描述这份开发集的审阅分类，不表述为模型通用准确率；引用、字段合法性、协议完成数、遗漏和错误分别列出。

审阅标注绑定各例原始文件的 SHA256。结果文件改变后，旧标注不得继续计数。报告同时显示原文、全部候选、原文验证问题、数量转换候选和审阅意见，供检查分类是否合理。

标注也绑定实验清单与用例集的 SHA256，改变模型身份或用例集后不可沿用旧计数。哈希只能防止误用旧记录，不能证明审阅独立或提供者身份。已提交的实验 JSON 保留原字节，固定用例/提示/schema 的换行，避免 Git 换行转换使标注失效。

本次实验还暴露了转换层缺口：正确保留的「延迟低于10毫秒」「至少要64GB」在 0.8 未成为量化目标。0.8.1 补足了单一明确数值表达前的对象标签和语气助词，仍拒绝多量值、复杂否定、不确定和不匹配引用。改进转换层不改变这批模型语义的审阅分类。


更强模型需先经独立文件哈希校验，再运行相同原始用例、提示和 schema，完成逐例复核后才比较。研究下载器可分块校验范围和长度、保存连续断点，完整 SHA256 通过后才将 `.part` 提升为模型；镜像仅作传输，期望哈希仍来自官方元数据。下载进行中不能算作模型已测。

### 与模型分类分开的产品过滤局限

用例 05 的“刚才编译很慢”使用 `past` 有原文支持，不能把最近一次体验当成已经退役的任务。用例 11 的 `excluded` 卡顿表示不允许卡顿；用例 28 的 `excluded` 离线渲染“快”表示不要求速度，不等于排除渲染任务。这三例没有因上述标签而被判错。

0.8.23 及此前的 `SemanticRequirements.Apply` 只将非 `past` 且为 `required` 的事项选入 active。因此，近期过去的体验或以排除不良体验表达的需求，可能未进入相应的活动需求判断；这是产品过滤规则的独立缺口，不能倒推模型使用 `past` 或 `excluded` 必然错误。

0.8.24 的改动将原文时间、原文关系与人工确认的购机用途分开：仍需满足、必须避免、不作为条件及用途待核对。过去或否定表达默认请求用途核对，明确选用后再进入配置建议与候选条件；不反转禁止事项的数值方向。修改内容会撤销用途和确认，过期的候选来源需处理后重新核对。[用途协议与流程](SEMANTIC_USE.md)说明边界。这里修复的是已给定事实的消费层，不是模型抽取质量；原始模型输出、分类及成绩保持不变。
