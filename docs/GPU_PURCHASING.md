# 把显卡观测转成选机顺序

配置分析的取舍摘要增加比较方向，显卡卡片可展开核显与独显三类整机的比较顺序。HTML 使用同一个 `GpuPurchasePlan`。它帮助决定先看哪些方案、带什么任务去比较，不生成型号跑分、价格或达标结论。

| 已取得的输入 | 优先比较什么 | 最能改变选择的检查 |
| --- | --- | --- |
| 已有分析判为核心/3D轻载，没有优先的新需求或重任务 | 核显整机与较低档独显整机进入首轮；当前级别或更强独显随后比较 | 同一个重要任务的实际表现与整机报价；核对软件功能、显示输出和共享内存影响 |
| 所选窗口只观察到编码、解码或媒体类别重载 | 先筛媒体功能，再比较核显或独显 | 软件实际调用、格式、位深、分辨率、并发路数；相同素材和质量设置下的耗时或丢帧 |
| 观察到图形、计算、复制重载，或保留较早核心/3D重任务 | 以当前重任务表现作基准，比较较低档方案 | 同任务帧率或耗时；当前体验未达目标且候选有收益时才讨论升级 |
| 新需求、体验问题、需求用途待定或条件需求 | 先按目标筛选，保留各条件分支 | 已有需求原文、用途和触发条件；历史轻载不能覆盖新任务 |
| 缺少有效观测、来源混合、历史或体验读取异常 | 先选择一个重要任务，不生成低负载选购优先级 | 各项异常仍由原入口显示和核对；缺数据也不能被解释为需要更高配置 |

媒体重载分类使用已有执行引擎类别，不从描述文字新增推断。复制与渲染/计算合并类别不按媒体处理。较早所选窗口重任务即使被近期媒体观测替换了展示标题，仍约束比较顺序。缺失引擎不补零，类别完整也不代表整卡覆盖；不改变原来的分析资格或候选确认。

技术依据：[NVIDIA Video Codec SDK](https://developer.nvidia.com/video-codec-sdk) 区分专用编解码硬件与 CUDA 核心；[NVENC 编程指南](https://docs.nvidia.com/video-technologies/video-codec-sdk/13.1/nvenc-video-encoder-api-prog-guide/index.html) 也说明部分功能会用 CUDA。[Intel 媒体引擎文档](https://www.intel.com/content/www/us/en/docs/oneapi/optimization-guide-gpu/2024-2/media-engine-hardware.html) 描述媒体硬件加速。这些资料支持按任务和引擎分别比较，不能证明某台核显机器能够替代用户的独显，也不能证明两种编码设置质量相同。

当前没有自动生成具体商品清单。候选规格、整机报价和同任务结果仍需取得；这份顺序表没有完成跨硬件校准或真实购机收益验收。模型默认关闭，自然语言抽取质量没有因本功能提高。
