# 候选配置比较

0.5.0 新增原生“候选配置”入口。它将已确认需求和候选报价、规格、任务结果放到同一份比较中，不根据旧机占用率乘以硬件跑分推算新机表现。

## 使用步骤

1. 添加两至三套候选。填名称、人民币整机报价、内存、独立显存、存储及 CPU/GPU 型号；记录报价单或商品页和日期。空白保留未知，共享内存不能填作独立显存。
2. 点击“导入当前需求与近期任务”。导入用户确认的非过去需求、当前分析范围的已观测场景（包含短时场景）、近期增加的负载和未解决体验问题。尚未结构化的需求全文也保留为待核对项目。
3. 核对每项条件，可修改或补充。能严格识别的单一预算上限、内存/显存/存储下限会提出数值候选；候选默认未核对。多个数值、偏好或含糊比较不猜测。GB/TB/MB 按十进制换算，报价支持元/万元，其他单位需先换算。
4. 便携、兼容、排除项等使用“逐项核对”，按完整条件检查；编译耗时、帧率、噪声等使用“实际任务测量”，设置目标方向、单位和统一测试步骤。相同软件、输入、设置、电源模式等是用户需要核对的实验条件，本程序不自动控制候选电脑。
5. 生成结果行，填写实测数值或核对结论、原始依据，并确认测试可比。配置表的容量和报价直接按规格比较，其他项目需要结果行。
6. 确认覆盖重要任务、新需求、近期体验及要保留的偶发任务，点击“保存并比较”。一套候选也可先保存为草稿。完整比较可导出 HTML。

## 判断规则

- 必需条件全部经过核对且有依据、需求范围未改变、用户确认覆盖后，候选才显示必需条件通过。明确不满足的条件显示失败；缺少规格、测量、来源或确认时保留待验证。
- 条件和不确定需求不挤进必需条件，分别显示触发条件及结果。每个条件还单独计算“必需条件 + 此条件”的最低已核对报价；多个条件同时触发时需核对全部相关项目，不枚举所有组合。基础最低报价并不是对条件触发后的全局推荐。
- 比较显示最低报价与其他通过方案的价差、容量变化，以及存在有效同条件测量时的原始任务结果。更高配置没有记录到任务收益，不等于已经证明冗余；条件任务仍可能需要它。
- 修改目标、触发条件、测试步骤或配置会使对应旧核对失效。只修改报价不会把 CPU/GPU 性能重新判定。需求、分析范围、近期增加或压力状态改变，会要求重新导入及确认覆盖。
- 导入保留已有手工修订和测量，用稳定来源编号去重；不自动删除旧条件，用户需移除已不适用项。重新导入后，条件必须重新核对。

数据保存在同一数据目录的 `comparison.json`，独立于采样保留期。原文件损坏时保留原件并禁止覆盖，不悄悄重置。报告对原文、名称、来源与测量记录进行 HTML 转义。

0.6.0 支持从“任务测量”导入重复耗时文件。首次导入绑定同一目标的测量协议，目标和结果需重新核对；显示中位数及各次范围，跨过目标线时保留待验证。比较文件升级为 `comparison-1.1`，旧版手工记录保留核对，旧客户端拒绝覆盖新版文件。详见 `TASK_MEASUREMENT.md`。

## 当前仍需完成

报价与手工测量由用户提供，未独立核实真实性；重复任务耗时可在各机器本地采集并导入，但机器映射、完整任务及未声明的资源仍需核对。没有自动硬件、实时价格或兼容性数据库，CPU/GPU 型号不产生性能排名。复杂自然语言约束、测量误差建模、报价时效及更便利的协议复用仍需完善。当前链路不是商业成熟度或跨机器性能准确性的证明。
