# 候选配置比较

0.5.0 新增原生“候选配置”入口。它将已确认需求和候选报价、规格、任务结果放到同一份比较中，不根据旧机占用率乘以硬件跑分推算新机表现。

0.8.29 的[规格摘录入口](SPECIFICATION_IMPORT.md)减少规格字段的重复填写。独立规格来源可用于容量目标，报价仍需自己的依据；comparison-1.4 保留原文和导入草稿，读取旧版时保留原有合并来源语义。冻结包已通过本机原生入口检查，未完成真实候选机标定。

0.8.28 的[购机建议与加价取舍](PURCHASE_SHORTLIST.md)按各个条件场景给出预算优先方案，区分任务收益、任务取舍和收益待核对。手填数值与重复耗时范围分别比较，不以型号或额外容量自动认定收益。

0.8.14 支持先核对一套候选是否达到目标，并从配置分析卡片进入比较页。入口保留当前分析范围，不自动创建条件或勾选确认；初步余量或疑似过剩用于提出比较方向，候选表现由逐项证据判断。

0.8.15 将报价资格与任务结果分开检查：任务已通过不再代替报价来源；未核对或核对签名过期的任务也不再进入价差中的收益对照。单候选、未填报价或待补报价来源时，仍可独立核对有依据的任务目标。

0.8.16 可把同一测量方案带到候选电脑，减少任务参数、版本、步骤和重复方式的重复填写。每台电脑仍需重新选择本机文件、核对环境并实际运行；方案没有耗时结果，不能单凭导入或勾选环境核对让候选通过。

## 使用步骤

0.8.20 修复待定事项的分组：“需求尚未确定：某事项”只是缺少触发信息的提示，相同提示下的不同事项分别比较，不推定同时成立。同一事实编译的区间上下界仍一起核对。若多个目标必须同时满足，请为它们填写相同的实际触发条件；未明确的多个情景不能直接拼成整机结论。情景标题同时列出对应项目以便区分。

比较文件升级为 comparison-1.3，防止旧版客户端按旧分组规则重新保存。可读取 1.0–1.2，保留原始候选、条件和测量证据；旧版待定条件的核对与覆盖确认撤销，重新核对后使用。读取不改写导入源文件；结果表的候选/条件名称由当前引用行生成，旧显示副本为空也不会显示空白。分析方法仍为 1.15，遥测历史不重算。

0.8.19 在保存或另存成功后解除此前的全局退出提醒，不覆盖其他操作的提示。创建备份时先将当前候选草稿保存到数据目录，包括尚未提交的有效单元格；草稿无法保存时，备份尚未开始，需修正内容或解除文件占用。外部导出可以保护退出时的唯一副本，但不等于该副本已进入数据目录备份。未保存测量也需先导出，另存文件单独保管；恢复入口继续可用。

候选页编辑后停顿约 1.25 秒会尝试自动保存草稿，也可点击页首“保存草稿”。空白容量、目标和未核对条件可以暂存，保存本身不生成结论。名称、重复项、单位或数值格式无效时会保留编辑并提示修正；尚未落盘的内容在正常退出时再次保存，失败则默认返回候选页。窗口收进托盘仍保持内存编辑，不代表已经保存。

“导出草稿”保存 comparison-1.3 JSON，可在另一个可写目录保留完整候选、条件、来源和原始测量。导出成功后可正常退出；再编辑会重新启用未保存保护。“导入草稿”先验证文件，在当前唯一草稿未保存且未导出时阻止替换；导入清空覆盖确认并撤下比较结果，按当前需求重新核对。JSON 只读取数据，不执行里面的任务文字。损坏的原 comparison.json 保留且禁止覆盖，可将当前新草稿另存导出。临时文件使用唯一名称，保存失败清理自己的临时文件，已有目标保留；这些检查不构成崩溃或断电恢复保证。

1. 添加一至三套候选。填名称、内存、独立显存、存储及 CPU/GPU 型号，记录规格来源；需要比较价格时再填人民币整机报价、出处和日期。单台可先不填报价核对任务与规格目标；报价目标本身仍需价格依据。空白保留未知，共享内存不能填作独立显存。
2. 点击“导入当前需求与近期任务”。导入用户确认的非过去需求、当前分析范围的已观测场景（包含短时场景）、近期增加的负载和未解决体验问题。尚未结构化的需求全文也保留为待核对项目。
3. 核对每项条件，可修改或补充。能严格识别的单一预算上限、内存/显存/存储下限会提出数值候选；候选默认未核对。多个数值、偏好或含糊比较不猜测。GB/TB/MB 按十进制换算，报价支持元/万元，其他单位需先换算。
4. 便携、兼容、排除项等使用“逐项核对”，按完整条件检查；编译耗时、帧率、噪声等使用“实际任务测量”，设置目标方向、单位和统一测试步骤。相同软件、输入、设置、电源模式等是用户需要核对的实验条件，本程序不自动控制候选电脑。
5. 生成结果行，填写任务数值或核对结论与依据，或点击“运行任务测量”进入测量页。可先保存方案，在各候选电脑复用并取得新的原始重复耗时文件，再回比较页选中对应行，点击“导入所选行的测量”，核对候选机器和测试可比性。配置表的容量和报价直接按规格比较，其他项目需要结果行；手填值与重复测量分别标注。
6. 确认覆盖重要任务、新需求、近期体验及要保留的偶发任务，点击“保存并比较”。一套候选即可显示逐项结果和必需条件结论，并可导出 HTML；添加更多候选后再比较价差。

## 结果中的证据类型

界面与 HTML 逐项显示证据类型，不把所有通过项统称为实测验证。

| 类型 | 判断依据与结果含义 |
| --- | --- |
| 规格 / 报价资料 | 按候选填写的容量、整机报价及来源核对数值目标；不代表任务性能测试 |
| 人工核对 | 用户按完整条件填写结论、依据并确认可比性，适用于兼容性等逐项检查 |
| 手填任务数值 | 按手填结果、统一步骤、单位及可比性核对目标；没有原始重复轮次，不能取得重复测量达标标签 |
| 重复耗时测量 | 导入原始正式轮次，经 `TaskMeasurements.Assess` 检查协议、执行状态、电源条件、显示值与目标；仅全部正式轮次达标时显示“重复耗时测量达标” |

重复结果全部未达标时显示未达标，跨过目标线、协议不符或核对失效时保留待核对；已经绑定测量协议的目标不能用手填值替代原始文件。整体 `pass` 仍表示“必需条件通过”，其中可以包含规格资料与人工核对。单项重复耗时达标只覆盖该任务的根进程退出耗时，机器对应关系、实际产物及已分离后台任务仍需核对；它不会自动把某个 GPU 或整机标为“实测已验证”。

方案复用时，可以在测量页导入方案或旧测量文件；旧测量只提供协议与环境声明，旧机器和旧耗时不会变成本机结果。导入清空本机路径并锁定协议字段，最终路径和本机环境需重新核对，只有点击运行才执行任务。协议或文件不符会在启动前阻止；需要改变条件时显式“作为新方案编辑”，再为不同协议建立对应目标。方案不打包文件或保存所选路径字段，但原样参数、步骤等文字可能含路径。自动保存失败的结果可在当前会话中保留并重试导出，退出前允许明确放弃；这不等于崩溃或磁盘恢复。完整流程见[任务测量与方案复用](TASK_MEASUREMENT.md)。

## 判断规则

- 0.8.2 检查整机报价、内存、独立显存和存储的共同数值范围。例如内存至少 64 GB 且不超过 32 GB，会显示具体冲突项目，要求先核对输入；必需条件冲突时整体保持待验证，不将它解释成所有电脑都不值得买，也不输出最低报价或节省金额。严格小于/大于与非严格边界分别计算，相等的闭区间可以成立；规格与报价不能为负数。
- 冲突检查包括尚未核对的数值草稿，不能代替原文审阅。每个条件情景只合并必需条件和同一触发条件；某情景冲突不会抹掉无条件比较，不同触发条件也不自动假定同时发生。多个条件同时触发仍需一起核对。不同任务可能都以秒计量，因此不会仅按单位把它们的上下界合并；人工核对项和复杂语义冲突仍需逐项检查。
- 必需条件全部经过核对且有依据、需求范围未改变、用户确认覆盖后，候选才显示必需条件通过。明确不满足的条件显示失败；某项所需的规格、测量、来源或确认缺失时，该项保留待验证。报价资格独立判断，缺少报价来源不取消已有独立依据的任务通过结果。
- 条件和不确定需求不挤进必需条件，分别显示触发条件及结果。每个条件还单独计算“必需条件 + 此条件”的最低已核对报价，同样只纳入金额和来源齐全的候选；缺少来源时提示待补，不将该金额用于情景排名。多个条件同时触发时需核对全部相关项目，不枚举所有组合。基础最低报价并不是对条件触发后的全局推荐。
- 单台核对不计算节省金额。至少两台候选同时通过必需条件、填写报价金额且来源非空白时，才比较它们的价差、容量变化和有效任务结果。缺少来源的原金额继续显示，并明确提示“待补报价来源”，不参与最低报价、价差或节省计算；更便宜但未通过必需条件的候选也不参与。来源填写检查不等于认证，程序未核实出处真实性、报价时效或商品信息。
- 任务收益对照要求目标已核对、核对签名仍匹配当前目标，且候选对应的证明、可比性和测量协议检查有效。取消核对或修改目标后，原始记录保留，未重新核对的数值不再显示为价差中的任务收益；重新核对且其他证据仍有效后可恢复。条件任务的对照始终标出触发条件，单项失效不抹去其他独立已通过目标。更高配置没有记录到任务收益，不等于已经证明冗余；条件任务仍可能需要它。
- 修改目标、触发条件、测试步骤或配置会使对应旧核对失效。只修改报价不会把 CPU/GPU 性能重新判定。需求、分析范围、近期增加或压力状态改变，会要求重新导入及确认覆盖。方法 1.13 同时绑定初步观测的分类与范围：轻载变为繁忙、来源范围改变需重新核对，普通数值、时长、覆盖比例及观测文案刷新不单独使确认失效。
- 导入保留已有手工修订和测量，用稳定来源编号去重；不自动删除旧条件，用户需移除已不适用项。重新导入后，条件必须重新核对。

数据保存在同一数据目录的 `comparison.json`，独立于采样保留期。原文件损坏时保留原件并禁止覆盖，不悄悄重置。报告对原文、名称、来源与测量记录进行 HTML 转义。

0.6.0 支持从“任务测量”导入重复耗时文件。首次导入绑定同一目标的测量协议，目标和结果需重新核对；显示中位数及各次范围，跨过目标线时保留待验证。比较文件当时升级为 `comparison-1.1`，旧版手工记录保留核对，旧客户端拒绝覆盖新版文件。详见 `TASK_MEASUREMENT.md`。

## 当前仍需完成

报价与手工测量由用户提供，未独立核实真实性；重复任务耗时可在各机器本地采集并导入，但机器映射、完整任务及未声明的资源仍需核对。没有自动硬件、实时价格或兼容性数据库，CPU/GPU 型号不产生性能排名。复杂自然语言约束、测量误差建模、报价时效，以及方案所引用的依赖和环境核对仍需完善。当前链路不是商业成熟度或跨机器性能准确性的证明。

0.8 的范围、严格边界和单位换算见 [量化目标说明](QUANTITY_GOALS.md)。内存、显存、卷容量遥测以 GiB 显示，手填候选规格仍按表头 GB；原始历史未重新缩放。
