# 商业级验收账本

本账本保留历史阶段与当前缺口。较早条目“原件/原目录保留”是当时的状态；已结束本机产物后来按用户清理授权收口，公开摘要和失败结论仍保留，不能据此宣称原始私有目录现在仍在。当前交付及独立长测状态以最新[验证记录](VALIDATION.md)为准。
0.8.34 用多款真实商品页修正了通用 CPU 帮助误入配置、明确总量/模块写法被留空的问题。三款官网 SKU 已从实际原生入口读取、保存并进入初筛，并与真实历史只读副本检查容量取舍；任务表现仍待候选机复测，没有自动确认。联想两款页面目前读取失败，未将它包装成已支持品牌；商品渠道覆盖与真实任务收益都还不足以证明商业成熟。

0.8.33 将同一会话中已完成的测量连接到明确选择的候选任务行：先核对来源机器与目标，再填入原始轮次，并撤销旧的目标/可比性/覆盖确认。省去寻找本机 JSON 文件，不自动关联机器或给出达标结论；跨电脑仍使用方案和原始测量文件。它改善了复测后的操作路径，真实候选机收益、独立用户验证及其他设备证据仍然缺少。

0.8.32 已把支持的官网具体 SKU 读取、候选草稿与自动初筛接通。本机实际读取一款 Dell 商品，并用真实历史只读副本检查容量取舍；没有候选机任务测量，未自动确认覆盖。页面可读取不代表所有 SKU、当地配送或最终成交可用，候选 CPU/GPU 的性能与加价收益仍待真实机器验证。

0.8.30 已把观测与数量目标整理成只读的四部件配置草案，初步减少用户手工推导容量和预算方向的工作，并保留独立条件方案。真实历史只读报告已核对，本机冻结包原生流程通过；具体 CPU/GPU 型号、在售商品、可靠报价与跨机器任务收益仍未闭环，不能据此认定商业成熟。规则见 [配置草案](CONFIGURATION_DRAFT.md)。

用户目标仍是 Windows 原生性能监测与下一台电脑配置选择，同时判断不足和冗余，理解需求文字，并遵循少返工协议。版本号、自测数量及候选草稿保存通过，都不能单独证明这个目标已经完成。
