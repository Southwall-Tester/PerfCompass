# 商业级验收账本

用户目标仍是 Windows 原生性能监测与下一台电脑配置选择，同时判断不足和冗余，理解需求文字，并遵循少返工协议。版本号、自测数量及候选草稿保存通过，都不能单独证明这个目标已经完成。

| 范围 | 需要证明的用户效果 | 当前依据与缺口 |
| --- | --- | --- |
| 监测可信度 | 在明确公布的支持范围内，CPU/单核、内存峰值/提交量、GPU 各执行引擎和磁盘线索能反映真实任务；故障、缺失、来源切换和换机不会生成虚假的低负载或余量 | 计时、覆盖、更新失败、硬件标识、来源隔离已有回归；本机有编解码受控任务和 API 对照。单机响应与 API 接近不能证明物理准确性、驱动内部新鲜度或其他设备支持。仍需支持矩阵和有代表性的实际设备验证。 |
| 不足与冗余的实用性 | 用户能得到有范围的保留/升级/比较较低配置方向，近期新增需求优先，偶发重任务与历史缺口可见；候选选择应能回到实际任务和体验验证 | 方法 1.15 已保留近期观测、条件分支及较早重任务；有实际入口、合成边界和手动候选核对。规则阈值与购机收益仍缺真实用户轨迹及候选机器任务的校准，不能用旧机利用率乘跑分代替。 |
| 自然语言到建议 | 不同表达中的任务、主体、肯否、时间、数量与条件可核对；原文、结构化事实、歧义和最终建议保持连通，错误不能默默变成建议 | 规则和可选模型均有反例与原始输出，数量转换独立检查；模型默认关闭。8B 的 36 例开发审阅有 7 完整、11 遗漏、18 错误，不是独立人工标注。24 条扩展输入的模型测试、逐例审阅及独立人工一致性仍未完成。 |
| 数据与操作保护 | 正常退出、暂存、导入导出、备份恢复、日期变化、读写失败等常用路径保留唯一内容；失败可见且有可操作的恢复路径 | 设置、历史、测量和草稿分别有保护及故障注入检查。0.8.18 增加候选草稿保存与退出保护，0.8.19 在创建备份前提交候选编辑，并阻止遗漏未保存结果的备份。崩溃、断电、磁盘恢复和所有系统退出路径没有被这些常规检查证明。 |
| 稳定性与开销 | 当前冻结版本在实际使用中有完整、可核对的持续运行终态；开销、采样新鲜度、异常与中断分别记录 | 旧 0.8.10 试验已观察到睡眠/校时保护，本轮复核进程不存在且缺最终结果，不能算作成功八小时，更不能代表新版本。新版本需要新的独立目录与冻结 EXE，未结束之前只报告进行中。 |
| 交付与易用性 | 从用户实际启动入口走通监测、分析、需求核对、比较、任务复测及数据保护；支持范围、安装/升级、隐私和故障说明与实际一致 | 本机独立发布包、自测、原生控件流程和实际视觉树截图有记录。系统文件对话框、完整鼠标/托盘/辅助功能、其他 DPI 与设备仍有缺口；商业代码签名与发行支持尚未完成。CI 只证明该提交在相应环境完成那些检查。 |

每次交付把“实现”“本机实测”“合成边界检查”“外部/其他机器验证”分别记录在 [验证记录](VALIDATION.md)。失败原件保留，重试使用新数据目录；某一项补齐不能把其他项目自动改成通过。没有逐项直接证据之前，持续目标保持未完成。

下一阶段优先补齐当前版本持续运行终态、真实入口的数据保护与输入语义覆盖，并取得支持范围内的跨机器及实际任务证据；不以添加无关功能替代这些缺口。
