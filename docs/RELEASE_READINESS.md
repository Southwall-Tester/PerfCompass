# 商业级验收账本

用户目标仍是 Windows 原生性能监测与下一台电脑配置选择，同时判断不足和冗余，理解需求文字，并遵循少返工协议。版本号、自测数量及候选草稿保存通过，都不能单独证明这个目标已经完成。

| 范围 | 需要证明的用户效果 | 当前依据与缺口 |
| --- | --- | --- |
| 监测可信度 | 在明确公布的支持范围内，CPU/单核、内存峰值/提交量、GPU 各执行引擎和磁盘线索能反映真实任务；故障、缺失、来源切换和换机不会生成虚假的低负载或余量 | 计时、覆盖、更新失败、硬件标识、来源隔离已有回归；本机有编解码受控任务和 API 对照。单机响应与 API 接近不能证明物理准确性、驱动内部新鲜度或其他设备支持。仍需支持矩阵和有代表性的实际设备验证。 |
| 不足与冗余的实用性 | 用户能得到有范围的保留/升级/比较较低配置方向，近期新增需求优先，偶发重任务与历史缺口可见；候选选择应能回到实际任务和体验验证 | 方法 1.15 已保留近期观测、条件分支及较早重任务；有实际入口、合成边界和手动候选核对。规则阈值与购机收益仍缺真实用户轨迹及候选机器任务的校准，不能用旧机利用率乘跑分代替。 |
| 自然语言到建议 | 不同表达中的任务、主体、肯否、时间、数量与条件可核对；原文、结构化事实、歧义和最终建议保持连通，错误不能默默变成建议 | 规则和可选模型均有反例与原始输出，数量转换独立检查；模型默认关闭。8B 的 36 例开发审阅有 7 完整、11 遗漏、18 错误；另 24 条扩展输入已完成实际调用及逐例开发审阅，4 完整、1 遗漏、19 错误。都不是独立人工标注，独立一致性与语义质量仍未通过。 |
| 数据与操作保护 | 正常退出、暂存、导入导出、备份恢复、日期变化、读写失败等常用路径保留唯一内容；失败可见且有可操作的恢复路径 | 设置、历史、测量和草稿分别有保护及故障注入检查。0.8.18 增加候选草稿保护，0.8.19 在备份前提交编辑；0.8.21 增加所选程序/输入的运行期普通写入保护，新旧测量方法分开，旧原始结果保留并要求复测。崩溃、断电、磁盘恢复、全部文件系统和系统退出路径没有被这些常规检查证明。 |
| 稳定性与开销 | 当前冻结版本在实际使用中有完整、可核对的持续运行终态；开销、采样新鲜度、异常与中断分别记录 | 旧 0.8.18 八小时试验已结束但未通过（一次界面调度超时与一次观察间隔异常），原始失败保留。0.8.25 本机短测与受控界面阻塞检查通过，独立八小时试验仍在运行。正式监督入口增加进程退出见证，但不能用工具短测补齐新版长测终态，也不能证明跨硬件或长期稳定性。 |
| 交付与易用性 | 从用户实际启动入口走通监测、分析、需求核对、比较、任务复测及数据保护；支持范围、安装/升级、隐私和故障说明与实际一致 | 本机独立发布包、自测、原生控件流程和实际视觉树截图有记录。系统文件对话框、完整鼠标/托盘/辅助功能、其他 DPI 与设备仍有缺口；商业代码签名与发行支持尚未完成。CI 只证明该提交在相应环境完成那些检查。 |

0.8.22 修复当前范围刷新期间旧建议仍可见、排队调用提前返回的问题；分析、候选比较和报告导出绑定最终当前范围，候选草稿可在等待期间保存。该修复属于同机入口正确性，不补齐上述跨设备、语义质量、持续稳定性或发行支持缺口。

0.8.23 将体验读取异常接到实际判断、报告和候选范围，避免损坏体验被误当作空历史。该项仍是读写完整性保护，不构成崩溃恢复、身份认证或跨机器校准。

0.8.24 将人工确认的购机用途连接到配置分析与候选条件，过去体验和否定表达不再被直接当成无购机用途；背景原文、触发条件和旧测量继续保留。该层消费已给定或已核对的事实，没有提高原始模型抽取成绩。用途核对的本机界面流程不代替独立用户验证或通用理解能力。

2026-10-24 的 [GLiNER2.5 专用抽取研究](https://github.com/Southwall-Tester/PerfCompass/blob/main/research/gliner/README.md)实际完成 24 条输入的 8 个组合，仍存在归属、分期与条件关系反例，未接入默认解析器。调用、位置匹配和四项脚本检查不等于语义质量；对照页的浏览器呈现与交互因工具不可用/自动审批拒绝而未完成。该研究不替代当前版本的长期验证或独立人工标注。

每次交付把“实现”“本机实测”“合成边界检查”“外部/其他机器验证”分别记录在 [验证记录](VALIDATION.md)。失败原件保留，重试使用新数据目录；某一项补齐不能把其他项目自动改成通过。没有逐项直接证据之前，持续目标保持未完成。

0.8.25 开发阶段将后台采样与界面刷新分开；0.8.24 冻结程序集的主动 UI 阻塞对照与开发版真实入口分别观察到历史停止/继续推进。独立 0.8.18 八小时试验已经结束但未通过：一次界面调度超时和一次观察间隔异常。实际起因尚未证实，修复不自动使旧结果通过，也不构成新版本八小时稳定性证据。详见 [验证记录](VALIDATION.md)。

下一阶段以真实购机决策为中心，优先验证配置取舍、可购买候选与同任务对照是否帮助缩小选择和减少无收益的支出；取得支持范围内的跨机器证据。持续运行、必要的数据保护和输入语义检查继续保留，不以扩张通用验证基础设施或测试数量代替购机价值。
