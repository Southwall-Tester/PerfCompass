PerfCompass 使用说明

0.8.33 · 分析方法 1.15 · Windows 开发试用版

开始记录

正常使用电脑，在右上角选择当前场景。实时概览显示当前 CPU、内存、GPU、磁盘活动，以及活跃应用。

关闭窗口后会继续在系统托盘记录。双击托盘图标恢复窗口；使用“退出程序”停止运行。

把本次测量用于候选核对

测量结束后，点击“到候选页核对本次测量”；在结果表选中对应候选和任务行，点击“使用本次测量”。先核对卡片中的目标与来源机器，再填入。目标、可比性和覆盖确认仍需重新核对，其他电脑的结果继续通过原始 JSON 导入。

具体商品与候选初筛

在候选配置点击“从商品链接添加”，读取支持的官网具体 SKU，核对选定规格和报价后添加。候选自动初筛会列出比较顺序、容量不符和待补任务。修改配置或金额后需补充实际报价来源；商品页面不代替候选机器任务实测。支持范围见 docs/PRODUCT_PAGE_IMPORT.md。

下一台电脑配置草案

配置分析顶部会自动整理处理器、内存、显卡与 SSD 的优先比较方案。单核短峰不会独自要求更多核心；内存保留物理峰值与当前可用容量，SSD 按占用提出商品容量档，显卡保留核显与独显的比较顺序。

条件成立时的方案单独展开，并附原文。商品标称 GB 与实测可用 GiB 分开核对；草案只读，不会添加候选或勾选确认。具体机器的任务表现仍需比较。

当前配置取舍

配置分析页和 HTML 报告先给值得比较的方向，再列下一步；展开“依据与适用范围”查看读数和适用任务，不必从整页限制条件中寻找结论。

  • CPU 已测轻载：先比较较少核心、单核性能相近的处理器，再用最重任务筛选。
  • 内存：按已测峰值与提交量筛选容量，在候选机器上重跑最重的多任务组合。
  • GPU 已测轻载：可先比较较低档显卡，再用目标画质、帧率、计算、编码和软件功能筛选。
  • 存储：按文件与增长量选容量，按实际任务耗时选速度。

体验问题、已确认需求与条件、近期新增重任务和压力线索优先。条件需求分别比较成立与不成立时的配置，不自动当作必需条件。初步余量提供比较方向，不会自动使候选达标；点击“比较候选配置”也不会自动勾选覆盖确认。

查看配置分析

已测任务可先形成初步判断，不必等满 10 小时、3 天。CPU/最忙逻辑核心与内存/提交量取得至少 5 分钟有效读数、覆盖至少 95%，GPU 核心/3D取得至少 5 分钟有效读数、覆盖至少 90% 且来源一致后，可形成初步余量判断。繁忙线索可以更早显示；缺失数据不填零，短峰也不直接称为持续压力。

卡片同时保留观测依据与配置结论。基础初步观测标明最近 7 天和所选场景，分引擎重任务标明所选时间窗口；已确认的新任务与未处理体验优先于轻负载建议显示，原有观测仍保留。

方法 1.15 另保留所选窗口内达到 90% 的有效核心/3D重峰。比如选择 30 天时，20 天前的重任务不会被最近 7 天轻载盖掉；主方向先保留该任务，再核对较低档候选。旧重峰与近期轻载分别标明时间和场景，不能将旧峰说成近期持续压力。硬件隔离、历史异常和来源边界继续适用。

“疑似过剩”或正式降档核对仍需至少 10 小时有效使用、跨 3 天、近期证据及典型任务确认。运行常用和偶发任务后，在记录设置确认当前硬件的覆盖情况；旧确认未绑定或硬件改变时需重新核对，历史保留。低 GPU 核心/3D负载不等于整张独显过剩；候选是否满足需求需分别核对。

近期需求变化

按场景查看最近 7/14/30/90 天。独立对照最近 7 天与此前 7 天、最近 30 天与此前 30 天；近期反复新增的重任务优先约束配置建议。缺少对照记录时继续积累，近期减少不代表过去任务永远不再需要。

冗余判断还需要最近 7 天至少 30 分钟、跨 2 天的有效观测及相关传感器证据。完整方法见 DEMAND_MODEL.md。

采集与数据

实时约 2 秒刷新，历史约 10 秒保存，新设置默认保留 90 天，可选 30/60/90 天；旧设置保持原值。纯空闲时段从配置过剩分析中排除，明显后台任务仍算有效使用。

数据位于程序旁的 data 文件夹。进程列表只实时展示。采样与进程不上传；报告和 CSV 由你主动导出。可选模型解析仅在点击发送时向所配服务发送需求描述。

硬件传感器的可用性取决于设备、驱动与权限。缺失值显示“—”，不会被当作零。传感器更新失败时，实时页显示设备与重试提示，该设备的旧读数不计入新观测，成功后自动恢复。基础 CPU 与内存采集使用 Windows API；温度等附加传感器可能不可用。

需求与体验

实时页可记录卡顿或等待，以及此前两分钟的采样线索。历史页可核对并标为已处理；同时出现高占用不能证明原因。

设置页支持有限规则预解析。逐项核对后确认保存，字段才参与配置建议；修改原文后需要重新解析。陌生任务、复杂条件、时间与数值仍可能无法识别，当前不是通用自然语言理解。研究与诊断见 docs/NLP_RESEARCH.md。

可选模型解析

在记录设置打开“模型解析与逐项核对”，配置接口后主动发送需求描述。候选默认不选用，可以修改、排除与补充，核对原文后保存才参与建议。密钥仅在当前运行保留。

条件与过去需求不作为必然的新任务；本机服务会暂停监测，请停止该服务后再继续。完整说明见 docs/MODEL_REQUIREMENTS.md；接口通过不代表模型语义质量通过。

比较候选配置

添加一至三套电脑，填写容量、型号与来源，导入已确认需求和近期任务，再核对目标与触发条件。一套候选即可核对任务和规格目标，不必先填写报价；报价目标本身仍需价格依据。进入比较页不会自动创建条件或勾选覆盖确认，缺少依据的项目继续待验证。

结果与 HTML 逐项区分四类依据：规格 / 报价资料、人工核对、手填任务数值、原始重复耗时测量。整体“必需条件通过”可包含资料与人工记录；只有原始重复耗时经协议及每轮目标校验通过的项目才标为“重复耗时测量达标”，不会自动把整机或显卡标为实测已验证。

核对重要和偶发任务后，点击“保存并比较”查看逐项结果并导出 HTML。至少两台有报价且通过必需条件的候选才计算价差。条件需求单列，配置、目标或测试步骤改变后需重新核对；预算和容量范围冲突时先核对输入，不同触发情景分别检查。详细流程见 docs/CANDIDATE_COMPARISON.md。

重复任务测量

选择会自行退出的程序、参数、输入文件及统一步骤，记录多次耗时，再在候选比较中导入对应任务行。保留各次范围，结果跨过目标时待验证。失败、取消、超时或协议不同不能当作更快。

程序与输入校验会影响缓存，不代表冷缓存性能；根进程退出也不证明分离后台任务已结束。测量期间暂停本实例的长期记录，结束后确认任务停止再继续。详见 docs/TASK_MEASUREMENT.md。

备份与恢复

创建前先保存当前候选草稿；保存失败或测量结果尚未保存时，备份不会开始，恢复入口继续可用。归档只包含数据目录中的文件，另存到其他目录的副本需单独保管。

在“记录设置 → 数据保护”保存备份。窗口打开时暂停监测，关闭后恢复此前状态。备份未加密，包含需求与任务参数，请放在可信位置。

选取备份校验后，恢复到新的独立目录；可用当前程序打开该目录，初始暂停监测和历史清理。重新启用清理前会显示过期文件数量。设置损坏时保留原件，尝试上次有效副本，并提示核对。普通设置修改不会自动解除恢复核对。

设置保存失败时，窗口上方会持续提示，需求与核对输入保留；排除文件占用、权限或空间问题后再次保存。场景失败时回到实际记录的场景。后台保存失败会尝试恢复原自启动项；无法确认时请核对 Windows 启动应用。

完整说明见 docs/DATA_PROTECTION.md。

量化目标与单位

核对模型候选时可查看量化比较目标。预算范围生成上下界，低于与不超过分别处理，毫秒、重量、续航、容量等按明确单位换算。原文数字、单位或边界不符时继续逐项核对。

内存、显存、卷容量遥测使用 GiB，进程内存用 MiB，读写速度用 MiB/s。候选规格表按 GB 比较，需核对厂商口径；旧历史数值未重算。详细说明见 docs/QUANTITY_GOALS.md。

历史记录异常

历史损坏、截断或无法读取时，窗口上方显示文件与行号，保留可用观测，暂不判断余量或时期变化。检查范围包含当前窗口和时期对照所需历史，至少最近 60 天。

原文件保留。可先备份，再从已核对的备份恢复到新目录。异常改变会取消旧的候选覆盖确认；异常消失后需要自己重新核对。格式检查不能证明漏采时段或已删除文件完整。详见 docs/DEMAND_MODEL.md。

重复记录与目录占用

相同记录按一次计入观测，并显示排除数量。不同记录的有效时段重叠时，按唯一时段计时，负载与配置判断待核对；场景时长可能重叠，不能相加。原始文件保留，CSV 保留可读取的原始行。

同一数据目录由一个新版实例使用，目录占用时请打开已运行的程序。升级前退出旧版本。空的 .perfcompass-instance.lock 文件可保留，退出后锁会释放。

采样时间中断

采样会交叉核对日历时间与经过时间，校验失败或间隔超过 15 秒时提示中断，重建基线后继续。该段不计入有效使用，也不当作空闲。

历史页和 HTML 报告显示中断数量，CSV 的 sampling_issue 列保留原因。暂停区间不累计。请保持系统日期正确；本程序不从网络校准系统时间。

清理日期核对

日期或时区变化、较长启动间隔、旧目录首次核对或清理日期记录损坏时，历史自动清理先暂停，普通监测可以继续。请在数据保护窗口核对系统日期、保留天数和到期名单，再决定是否恢复清理。

确认后的名单、设置或文件内容有变化时，需要重新预览。校验阶段可取消，删除开始后无法取消本批次；请先保存备份。具体机制见 docs/DATA_PROTECTION.md。

后台单核任务

单个逻辑处理器繁忙、低吞吐但繁忙的磁盘也计入活动线索，整机平均占用较低时仍保留任务时长和峰值。活动不直接证明瓶颈。

升级活动规则后，请在当前版本重新运行典型任务并核对覆盖确认；旧版漏记的时长无法补回。新记录和 CSV 保留活动规则版本。

CPU 计时完整性

整机 CPU 与最忙单核需要完整的处理器计时。处理器记录缺失、没有增量、计时回退或增量矛盾时，本次显示未知，重建基线后恢复。内存和 GPU 独立继续。

未知计时不当成 0% 或 100%，也不增加 CPU 覆盖时长。旧历史没有原始计时，无法追溯重算；真实热插拔和多处理器分组硬件尚需另行验证。

显卡分引擎观测

实时页和配置分析可展开查看已取得的核心、3D、计算、视频、编码、解码、视频处理和复制读数。旧核心/3D历史不变；没记录到的引擎仍未知，不回填为零，也不表示硬件不支持。

近期引擎重任务会约束降档方向，低核心占用不能证明整张独显多余。类别完整只表示已暴露的同类节点读数有效，不保证全部GPU覆盖或驱动数据新鲜。升级活动规则后请重新运行典型任务并核对覆盖确认。

核对历史时段

历史曲线按每项读数实际覆盖的秒数计算小时均值。选择“查看时段”，可看到该时段的 CPU、内存、GPU 均值和各自读数时长。小时均值包含有读数的空闲时段，选机建议单独分析活动任务。

跨小时的记录按区间分摊；部分读数无法定位到具体时刻时显示估计标记。报告中的“历史小时均值与观测时长”可展开查看同一明细。

从规格摘录添加候选

在候选配置页展开“从规格摘录添加候选”，填写资料来源，粘贴带字段名的中英文规格文本，再点击“生成规格预览”。逐项核对型号、CPU、GPU、内存、独立显存和存储容量，修订字段后添加候选。不明确的容量可留空。

规格来源与原文会随候选草稿保留；它们不充当报价依据。报价与对应来源在候选表另填。修改原文或来源后需重新生成预览；重新生成会替换预览字段。当前支持结构化规格表，尚未提供在线商品抓取。

新比较草稿为 comparison-1.4，可读取旧版文件；旧程序不能读取新文件。升级前请保留原始备份。添加候选不会自动核对条件或运行任务。

候选草稿

候选页结束当前单元格编辑后自动保存，也可点击“保存草稿”。保存失败或数值填错时，正常退出默认保留编辑内容；可以修正后重试，或“导出草稿”到其他目录。成功导出后可以退出，再编辑须重新保存。“导入草稿”会清空覆盖确认，需核对当前需求与来源后再比较。

报价与任务对照

任务条件可以独立通过。缺少报价来源的金额会保留并提示补充，补齐后才能参与最低报价和价差计算。取消核对或改过目标的任务，会退出收益对照，其他已通过条件保留。

在另一台电脑复测同一任务

测量期间限制对所选程序和输入的普通写入与替换，输出请写到其他文件。输入被其他程序写入时会在启动前提示。选择清单只保护该清单，不自动保护其中列出的文件。新测量与方案为 1.1；旧记录保留，导入旧任务安排后按新方法复测。

在“任务测量”填写任务后点击“保存测量方案”，无需先运行。将方案带到候选电脑，点击“导入方案或既有测量”，重新选择本机程序、工作目录和输入文件，再核对本机电源模式与软件设置。

方案保留参数、版本、步骤、重复次数及文件校验值；保存和导入不会执行任务。只有点击“运行并重复测量”才启动程序，开始前会检查与方案是否一致。需要改变条件时，点击“作为新方案编辑”。参数和步骤中的手填路径仍会保留，跨机请使用相同文件名及相对路径。

导入既有测量只复用任务安排，不把原机器的耗时当作本机结果。新结果可导出到候选配置页比较。自动保存失败时，结果留在测量页，可导出到其他目录；退出前可选择保留结果或明确放弃。

核对需求怎样影响选机

在记录设置展开逐项核对需求，可手工补充事项，或主动使用已配置的模型。核对原文后，选择仍需满足或验证、必须避免、不作为购机条件或用途待核对。

原文时间保持独立：昨天发生的问题仍可作为下一台要解决的目标。修改事项会撤销用途与确认；用途变化后，候选旧条件需要重新处理和核对，原始目标与测量保留。模型默认关闭，当前仍需人工核对。

体验记录读取异常

体验记录无法完整读取时，配置分析和历史页会显示文件与行号，报告会保留这些信息。已读体验和性能观测继续显示。请保留原文件，核对备份后恢复到新目录；修复后候选覆盖范围需要重新确认。

分析更新与报告

切换范围或场景、保存需求与体验后，配置分析会先显示更新状态，完成后恢复比较。等待时仍可编辑和保存候选草稿。导出报告会等待当前范围；读取失败时可点击刷新重试。

报告用途

HTML 报告可以在浏览器打开并打印为 PDF。内存容量建议、CPU 多核余量、GPU 使用情况及未来需求会一并保留，供你比较下一台电脑。

规则版本 1.15。5 分钟用于形成初步观测，10 小时 / 3 天及近期覆盖用于进一步评估配置，都是尚待跨机器校准的启发式门槛。GPU 利用率、CPU 占用与真实体验并非一一对应，短峰可能被采样遗漏。当前仍为开发试用版。
