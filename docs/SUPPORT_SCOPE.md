# 试用版支持范围与升级

本文对应已冻结的 **0.8.29**。当前为 Windows 开发试用版；实际入口版本以包内 `READY` 和程序左下角版本为准。源码工作区的新开发内容不能沿用冻结包的验证结果。

## 当前能证明的范围

| 范围 | 已有依据 | 使用时的边界 |
| --- | --- | --- |
| 发行平台 | `win-x64` 自带运行时的 WPF 便携包；本机 Windows x64 原生入口与解压入口已运行 | 尚未形成 Windows 版本、设备与 DPI 的完整兼容矩阵；没有 ARM64 或其他操作系统发行包 |
| CPU、最忙逻辑核心和内存 | 0.8.29 原生入口能取得本机实际读数；不完整计时、更新失败等另有注入回归 | 本机成功不等于跨 CPU 型号、多处理器分组或物理热插拔验证；未知读数不能填为零 |
| GPU 采集 | 本机 NVIDIA GeForce RTX 5060 Laptop GPU 有真实读取；0.8.17 另有带原始记录的受控编解码响应与身份探针 | 旧版任务实验不代替 0.8.29 负载校准；未证明其他显卡、核显、多卡或其他驱动组合的采集质量 |
| 存储容量 | 按已取得的固定卷合计读数，分别显示实际占用与商品容量换算 | 不等于唯一用户文件总量，也不提供 SSD 速度档位认证 |
| 配置与候选 | 原生条件核对、独立规格/报价来源、任务导入及预算方案已通过合成流程 | 当前没有完成真实候选机购机收益标定；通过规格条件不等于任务性能通过 |
| 持续运行 | 0.8.29 最终 EXE 的独立八小时试验已启动，由正式监督进程保存退出见证 | 运行中不算通过。0.8.25 旧试验缺终态与退出见证，保留为未完成，不转作本版证据 |

本表中“未验证”表示缺少对应设备或场景的直接证据，不表示该设备必然不支持。传感器未取得时，程序应保留未知并说明范围；不能据此判断用户负载轻或硬件多余。不同 GPU 来源的读数也不能直接合并成连续趋势。

完整版本、EXE 摘要、失败记录和验证范围见 [验证记录](VALIDATION.md)；原始编解码实验的公开摘要见 [本机 GPU 任务记录](experiments/gpu-workload-0.8.17-local.json)。

0.8.29 的对应远端构建已成功，本机默认入口已提升到同一冻结 EXE，更新前后用户历史摘要未变；详见 [CI 与默认入口记录](experiments/release-0.8.29-ci-promotion.json)。这不替代仍在运行的八小时试验。

## 启动与升级

1. 将便携包完整解压到可写的普通本地目录，再运行 `PerfCompass.exe`。发布包自带运行时，不需要安装 Python 或预装 .NET。程序按当前用户权限运行，不自动申请管理员权限。
2. 独立解压包默认使用程序旁的 `data`。本仓库的 `启动.cmd` 则优先使用 `release-next`，并明确读取 `release/data`；两种入口的数据位置不同。升级前先确认正在使用的目录。
3. 在“记录设置 → 数据保护”保存备份，并另外保管导出到数据目录外的草稿或测量文件。内置备份不收录这些外部文件。
4. 正常退出旧实例后，再使用新版本打开需要的目录。升级包先放在新目录，保留旧包；不要覆盖正在运行的 EXE。新旧实例不能同时使用同一数据目录。
5. 0.8.29 使用 `comparison-1.4`，旧程序会拒绝新比较文件。需要回到旧版本时，保留新目录，使用升级前的备份在新恢复目录中打开；不要让旧程序重存新格式数据。恢复后默认暂停记录与清理，按界面核对后再继续。

备份的校验值用于检查内容一致性，不是身份认证或断电恢复保证。恢复的具体操作与范围见 [数据保护](DATA_PROTECTION.md)。

## 出现问题时

先记录应用版本、发生时间、所选场景与分析窗口，并区分实时未知、历史读取异常、候选条件待核对和任务执行失败。历史异常可按界面的文件与行号核对原件；保存失败时优先保留当前编辑或导出到另一个可写目录。不要为让结果变绿而删除原始失败或勾选未经核对的条件。

查看日志或分享报告前先核对内容：需求原文、体验备注、参数、规格摘录及其中的路径可能随数据和报告保留。定位普通问题可以先提供已遮盖私人内容的界面、版本与操作步骤，无需默认提交全部使用历史。采样和进程信息不自动上传；可选模型仅在主动解析时向所配服务发送需求文字。

尚未完成的发行与体验工作，包括商业代码签名、其他设备与 DPI、完整鼠标/托盘/辅助功能路径、语义质量及真实候选机标定，继续在 [商业级验收账本](RELEASE_READINESS.md) 中保留。
